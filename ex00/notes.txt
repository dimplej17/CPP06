What is a static function?
A static member function belongs to the class, not an object.
Normal member function:
Dog d;
d.bark();

Static member:
Math::sqrt(...);
ScalarConverter::convert(...);

No object exists.
You're just calling a utility function that lives inside the class.

The class is just a container for static functions.

The four C++ casts
Before C++, people wrote
int i = (int)d;
The problem is that this one syntax could mean lots of different things. C++ introduced four different casts, each with one clear purpose.
Think of them as four different tools.

① static_cast
Purpose: Normal, safe conversions that the compiler understands.
Examples:
double d = 4.2;
int i = static_cast<int>(d);
or
int i = 65;
char c = static_cast<char>(i);
or
float f = static_cast<float>(i);
This is exactly what you're doing in this exercise.

② dynamic_cast
Used with inheritance.
Imagine:
Animal
   ↑
 Dog
Suppose you have
Animal* a = new Dog();
Later you wonder
"Is this Animal actually a Dog?"
You can ask
Dog* d = dynamic_cast<Dog*>(a);
If it really is a Dog, great.
Otherwise you get nullptr.
You'll probably use this in a later CPP module.

③ const_cast
Only changes constness.
Example
const int x = 5;
Normally
x = 6;
is illegal.
const_cast can remove const (although modifying an originally const object is often undefined behavior).
It's a very specialized cast.

④ reinterpret_cast
This one is the scary one.
It basically says
"Treat these bits as though they were another completely unrelated type."
For example
int x = 42;
int* p = &x;
char* c = reinterpret_cast<char*>(p);
Now you're pretending an int* is a char*.
Or
long address = 123456;
int* p = reinterpret_cast<int*>(address);
You're literally pretending some number is a memory address.
This is extremely powerful and extremely dangerous.
You almost never use it unless you're doing low-level programming.

So if an evaluator asks
Why static_cast instead of reinterpret_cast?
A good answer is
Because I'm converting between compatible scalar types (int, char, float, double). reinterpret_cast is for reinterpreting memory as another type, not for numeric conversions.


enums? - then, scoped vs. unscoped enums
An enum (enumeration) in C++ is a user-defined data type used to assign human-readable names to a fixed set of integral constants, 
making code cleaner and easier to maintain. Modern C++ introduces scoped enums (enum class), which are strongly typed and highly 
recommended over traditional, unscoped enums.

The Modern Way: Scoped Enums (enum class)
Introduced in C++11, enum class solves naming conflict issues by forcing you to scope the values, and it prevents accidental mathematical operations on your categories.
1. Definition and Usage
#include <iostream>
// Define a scoped enum
enum class TrafficLight {
    Red,
    Yellow,
    Green
};

int main() {
    // To use it, you must use the scope resolution operator (::)
    TrafficLight currentSignal = TrafficLight::Red;

    // Commonly paired with switch statements
    switch (currentSignal) {
        case TrafficLight::Red:
            std::cout << "Stop!" << std::endl;
            break;
        case TrafficLight::Yellow:
            std::cout << "Caution!" << std::endl;
            break;
        case TrafficLight::Green:
            std::cout << "Go!" << std::endl;
            break;
    }
    return 0;
}

2. Advanced Scoped Enum Customization
By default, the compiler assigns integer values starting at 0 (Red = 0, Yellow = 1, Green = 2). You can explicitly override these 
values and even change the underlying data type to optimize memory usage (like using a 1-byte char instead of a 4-byte int).cpp
// Change underlying type to unsigned char and give custom values
enum class StatusCode : unsigned char {
    Success = 200,
    NotFound = 404,
    InternalError = 500
};

int main() {
    StatusCode code = StatusCode::NotFound;

    // Scoped enums require an explicit cast to get the raw integer value
    std::cout << "Error code: " << static_cast<int>(code) << std::endl; 
    
    // In C++23, you can use std::to_underlying(code) instead of static_cast
    return 0;
}

The Legacy Way: Unscoped Enums (enum)
Traditional enums export their constant names directly into the surrounding scope. This means two different unscoped enums 
cannot share the same item names without creating a compiler error.
enum Color {
    Red,   // Implicitly 0
    Green, // Implicitly 1
    Blue   // Implicitly 2
};

// UNCOMMENTING THIS CAUSES COMPILER ERROR: "Red" is already defined in this scope
// enum Alert { Red, Warning }; 

int main() {
    Color myColor = Green;

    // Unscoped enums implicitly convert to integers
    int numericValue = myColor; 
    std::cout << "Value: " << numericValue << std::endl; // Outputs 1
    
    return 0;
}



What does static_cast<char>(d) do?
When you convert a floating-point type to an integer type (and char is an integral type), 
the fractional part is discarded (truncated toward zero).
So conceptually, C++ does this:
65.9
   ↓
65
Not
66
There is no rounding.
