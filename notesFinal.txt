cpp06 is one of the modules where evaluators often ask **conceptual questions** rather than trying to break your code. They want to know whether you understand *why* each cast exists.

Here's what I'd prepare.

---

# General

## Q. Why are there four C++ casts?

Because each one solves a different problem safely.

| Cast               | Purpose                                             |
| ------------------ | --------------------------------------------------- |
| `static_cast`      | Safe compile-time conversions between related types |
| `dynamic_cast`     | Runtime checked casts in inheritance hierarchies    |
| `reinterpret_cast` | Reinterpret raw bits as another type                |
| `const_cast`       | Add/remove `const` or `volatile` qualifiers         |

---

## Q. Why shouldn't we use C-style casts?

Because

```cpp
(int)x
```

doesn't tell you **what kind of cast** is happening.

It could behave like several different C++ casts.

C++ casts are explicit and much safer.

---

# ex00 (ScalarConverter)

---

## Q. Why use `static_cast`?

Because you're converting between compatible scalar types.

Example:

```cpp
double d = 42.5;

int i = static_cast<int>(d);
```

No runtime check is needed.

---

## Q. What is implicit casting?

The compiler converts automatically.

Example

```cpp
int i = 42;
double d = i;
```

---

## Q. What is explicit casting?

You write the conversion yourself.

```cpp
double d = 42.8;

int i = static_cast<int>(d);
```

---

## Q. Why prefer explicit casts?

Because they make potentially lossy conversions obvious.

---

## Q. What happens here?

```cpp
static_cast<int>(42.9)
```

Answer:

```text
42
```

Fractional part is discarded.

---

## Q. What happens here?

```cpp
static_cast<char>(65.9)
```

Answer:

First becomes

```text
65
```

then

```text
'A'
```

because ASCII 65 is `'A'`.

---

## Q. Why does

```cpp
300
```

become a strange char?

Because converting an out-of-range integer to `char` is implementation-defined.

That's why your program checks the integer range before casting.

---

## Q. What are pseudo literals?

```
nan
nanf
inf
+inf
-inf
inff
+inff
-inff
```

They represent special floating-point values.

---

## Q. What does `std::stod()` throw?

Usually

* `std::invalid_argument`
* `std::out_of_range`

Both derive from `std::exception`.

---

## Q. Why use `stod()`?

Because it

* parses signs
* parses decimals
* detects overflow
* throws exceptions

instead of forcing you to write everything yourself.

---

## Q. Difference between `float` and `double` literals?

```
4.2f
```

is float.

```
4.2
```

is double.

The `f` suffix literally means

> "this literal has type float."

---

# ex01 (Serializer)

---

## Q. Why use `reinterpret_cast`?

Because you're **not converting the object**.

You're converting

```text
pointer
↕

integer representing the same address
```

---

## Q. What is `uintptr_t`?

An unsigned integer type guaranteed to be able to hold a pointer.

---

## Q. Does serialization copy the object?

No.

It only stores the address.

---

## Q. Does deserialize create a new object?

No.

It reconstructs the same pointer.

---

## Q. Why compare

```cpp
deserialize(raw) == ptr
```

?

Because they should point to exactly the same object.

---

## Q. What is actually changing?

Only the type.

The address stays identical.

---

## Q. Is hexadecimal involved?

Not really.

Hex is only a way of printing the address.

---

# ex02 (dynamic_cast)

---

## Q. Why must Base have a virtual destructor?

Because polymorphism requires at least one virtual function.

Without one

```cpp
dynamic_cast
```

won't work.

Also, deleting a derived object through a `Base*` requires a virtual destructor for correct cleanup.

---

## Q. Why is the destructor virtual?

Suppose

```cpp
Base* p = new A;

delete p;
```

Without a virtual destructor

only

```text
Base::~Base()
```

would run.

The derived destructor wouldn't.

---

## Q. Why does `dynamic_cast` need polymorphism?

Because it uses runtime type information (RTTI).

Only polymorphic classes have RTTI.

---

## Q. What makes a class polymorphic?

At least one virtual function.

Usually

```cpp
virtual ~Base() {}
```

is enough.

---

## Q. Pointer version

```cpp
dynamic_cast<A*>(p)
```

If it fails?

Returns

```cpp
nullptr
```

---

## Q. Reference version

```cpp
dynamic_cast<A&>(p)
```

If it fails?

Throws

```cpp
std::bad_cast
```

---

## Q. Why the difference?

Pointers can be null.

References cannot.

So failure for references is reported via an exception.

---

## Q. Why can't you use a pointer inside

```cpp
identify(Base&)
```

?

Because the subject explicitly forbids it.

They want you to demonstrate that you know the reference form of `dynamic_cast`.

---

## Q. Why is `typeid` forbidden?

Because otherwise the exercise becomes trivial.

They specifically want you to learn `dynamic_cast`.

---

# `= delete`

---

## Q. What does

```cpp
Foo() = delete;
```

mean?

The constructor exists but cannot be called.

Attempting

```cpp
Foo f;
```

produces a compile error.

---

## Q. Why delete the constructor in Serializer/ScalarConverter?

Because those classes only contain static methods.

Creating objects makes no sense.

---

## Q. Difference between private constructor and deleted constructor?

Private:

Someone inside the class (or a friend) can still call it.

Deleted:

Nobody can call it.

Even member functions can't.

---

# `static`

---

## Q. What is a static member function?

It belongs to the class itself.

No object is needed.

Example:

```cpp
ScalarConverter::convert(...)
```

---

## Q. Can a static member access non-static members?

No.

There is no `this` pointer.

---

# Possible trick questions

## Why not use `dynamic_cast` in ex00?

Because there is no inheritance.

Only scalar conversions.

---

## Why not use `reinterpret_cast` in ex00?

Because you are converting values, not reinterpreting memory.

---

## Why not use `static_cast` in ex01?

Because pointer ↔ integer conversion is exactly what `reinterpret_cast` is for.

---

## Why not use `reinterpret_cast` in ex02?

Because you need runtime type checking.

`reinterpret_cast` performs no check and would be unsafe.

---

# Tiny syntax questions they sometimes ask

What does

```cpp
Base* p = new A;
```

mean?

`p` has static type `Base*`, but it points to an object whose dynamic type is `A`.

---

Difference between

```cpp
Base*
```

and

```cpp
Base&
```

A pointer can be `nullptr` and can be reassigned. A reference must always refer to a valid object after initialization and cannot be reseated.

---

## Three questions I'd almost guarantee you'll get

1. **Explain the difference between `static_cast`, `dynamic_cast`, and `reinterpret_cast`.**
2. **Why does `dynamic_cast` require a virtual function in the base class?**
3. **Why does the pointer version return `nullptr` while the reference version throws `std::bad_cast`?**

If you can answer those clearly, plus explain each of your own implementations, you'll be in a very strong position for the evaluation.
